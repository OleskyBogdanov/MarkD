# MarkD

Настольный редактор переносимых документов для macOS и Windows. `.markd` содержит текст, таблицы, слои, изображения и настройки оформления. Встроенные шрифты не требуют установки в ОС.

## Скачать MarkD 0.4.2

Сборки доступны в [GitHub Releases](https://github.com/OleskyBogdanov/MarkD/releases/tag/v0.4.2):

| Система | Файл |
| --- | --- |
| macOS Apple Silicon (M1 и новее) | `MarkD-0.4.2-arm64.zip` |
| macOS Intel | `MarkD-0.4.2-x64.zip` |
| Windows x64 | `MarkD-Setup-0.4.2-x64.exe` |

На macOS распакуйте ZIP и перенесите `MarkD.app` в «Программы». На Windows запустите установщик; можно выбрать каталог установки. Документы и пользовательский профиль сохраняются отдельно от приложения.

Эти сборки предназначены для ручной установки: macOS использует ad-hoc подпись без Developer ID/notarization, а установщик Windows не подписан сертификатом издателя. ОС может показать предупреждение о неизвестном разработчике. Автообновление в этих пакетах не включено; подписанный канал описан ниже.

## Что изменилось в 0.4.2

- Панель выбранной таблицы компактно переносит группы на узких окнах без горизонтального скролла. Шрифт, размер, цвет и выравнивание доступны напрямую; дополнительные параметры и удаление — в меню панели.
- Выбор элемента в «Структуре» прокручивает документ к самому элементу, включая повторный выбор и переход на другой лист.
- Ctrl+колесо плавно меняет масштаб документа от 25 до 200%. Размеры текста и ячеек остаются в координатах документа; масштабирование не вызывает ложные предупреждения о переполнении.
- Сохранены редактирование на холсте, выделение диапазонов таблицы, добавление строк и столбцов рядом с таблицей, Undo/Redo и экспорт PDF.

## Работа с документом

- «Новый проект» создаёт заготовку КП, «Пустой документ» — пустой лист, «Из шаблона…» — новый документ без перезаписи исходного файла.
- Основная кнопка «Сохранить» и Cmd/Ctrl+S сохраняют файл; Cmd/Ctrl+Shift+S открывает «Сохранить как». В меню «Файл» доступны открытие, копия, шаблон и «Показать файл». Сохранение копии/шаблона не меняет рабочий путь и признак несохранённых изменений.
- При закрытии окна, выходе, создании или открытии другого документа можно сохранить изменения, отказаться от них либо отменить действие. Ошибка записи и отмена выбора пути оставляют редактор открытым.
- Добавление использует текущую страницу. Выберите её в нижней строке состояния или щёлкните по листу. Меню рядом с номером страницы позволяет дублировать, перемещать и удалять страницы с Undo; последний лист удалить нельзя. Продолжения длинной таблицы остаются частью исходной страницы.
- Cmd/Ctrl+Z отменяет объектные операции, Cmd/Ctrl+Shift+Z повторяет; внутри текстового поля действует текстовая история. Cmd/Ctrl+D дублирует выбранный объект.
- «По ширине», «Вся страница» и масштаб находятся внизу окна. Команды документа и контекстное форматирование — над холстом; «Структура» открывает список слоёв и элементов. Содержимое редактируется прямо на холсте. Предпросмотр и PDF фиксируют последний ввод перед отображением/экспортом.

## Черновики и резервные копии

После изменения документа MarkD записывает recovery-снимок примерно раз в секунду после попадания ввода в модель. После аварийного завершения стартовый экран предлагает восстановить его или удалить. Это не заменяет обычное сохранение: последние символы до записи снимка могут не восстановиться. Черновик хранится только локально; исходный `.markd` автоматически не перезаписывается.

В каталоге `userData` находятся `recovery.json`, предыдущий `recovery.json.bak` и `logs/`. Обычно это `~/Library/Application Support/MarkD` на macOS и `%APPDATA%/MarkD` на Windows; имя зависит от установленной сборки. Точное расположение журналов открывается через «Помощь → Показать папку с журналами». E2E используют отдельные временные профили.

При обычном сохранении предыдущая версия файла остаётся рядом как `.markd.bak`. Чтобы открыть её вручную, **скопируйте** её под новым именем с расширением `.markd`. Ошибка замены файла больше не приводит к удалению оригинала.

## Разработка и проверки

Используйте Node.js **24.20.0** из `.nvmrc` (минимум 24.19), затем:

```bash
npm ci
npm run dev
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run deps:deprecated
```

E2E запускают Electron с production renderer и временными данными; на Windows используется видимое тестовое окно, на macOS — скрытое. CI проверяет macOS arm64, macOS Intel и Windows x64, выполняет запуск упакованных приложений и проверяет установленный NSIS-пакет. После успешного job готовые ZIP/EXE доступны в артефактах `installers-*`. Результаты конкретного запуска доступны в Actions.

## Локальная упаковка

```bash
npm run package:mac
npm run package:win
npm run smoke:win # только на Windows, после упаковки
```

macOS: локальная ad-hoc `.app` в `dist-package/mac-arm64/` или `dist-package/mac/` для Intel, с автоматическим smoke. Windows: NSIS `.exe` и `win-unpacked/`. Эти пакеты не включают рабочий канал автообновлений.

## Обновления без ручного скачивания

Встроен `electron-updater 6.8.9`: проверка, загрузка, состояние и контролируемый перезапуск. Для активации нужна **одна переходная установка подписанного выпуска** с HTTPS-каналом. После неё пакеты загружаются внутри MarkD; автоматическая установка при обычном выходе отключена. Без настроенного выпуска интерфейс сообщает, что обновления недоступны.

Источник обновлений — публичные GitHub Releases `OleskyBogdanov/MarkD`; отдельный сервер и токен на компьютере пользователя не нужны. Workflow собирает три подписанных пакета и полный черновик релиза. Настройка сертификатов, публикация через GitHub и проверка N → N+1 описаны в [руководстве выпуска](docs/releasing.md). Реальное обновление двух подписанных установок ещё требует проверки после настройки сертификатов.
