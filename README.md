# MarkD

Настольный редактор переносимых документов для macOS и Windows. `.markd` содержит текст, таблицы, слои, изображения и настройки оформления. Встроенные шрифты не требуют установки в ОС.

## Работа с документом

- «Новый проект» создаёт заготовку КП, «Пустой документ» — пустой лист, «Из шаблона…» — новый документ без перезаписи исходного файла.
- Основная кнопка «Сохранить» и Cmd/Ctrl+S сохраняют файл; Cmd/Ctrl+Shift+S открывает «Сохранить как». В соседнем меню доступны копия, шаблон и «Показать файл». Сохранение копии/шаблона не меняет рабочий путь и признак несохранённых изменений.
- При закрытии окна, выходе, создании или открытии другого документа можно сохранить изменения, отказаться от них либо отменить действие. Ошибка записи и отмена выбора пути оставляют редактор открытым.
- Добавление использует текущую страницу. Выберите её в панели страниц или щёлкните по листу. Страницы можно дублировать, перемещать и удалять с Undo; последний лист удалить нельзя. Продолжения длинной таблицы остаются частью исходной страницы.
- Cmd/Ctrl+Z отменяет объектные операции, Cmd/Ctrl+Shift+Z повторяет; внутри текстового поля действует текстовая история. Cmd/Ctrl+D дублирует выбранный объект.
- «По ширине», «Вся страница» и кнопка «Свойства» помогают работать в небольшом окне. Предпросмотр и PDF фиксируют последний ввод перед отображением/экспортом.

## Черновики и резервные копии

После изменения документа MarkD записывает recovery-снимок примерно раз в секунду после попадания ввода в модель. После аварийного завершения стартовый экран предлагает восстановить его или удалить. Это не заменяет обычное сохранение: последние символы до записи снимка могут не восстановиться. Черновик хранится только локально; исходный `.markd` автоматически не перезаписывается.

В каталоге `userData` находятся `recovery.json`, предыдущий `recovery.json.bak` и `logs/`. Обычно это `~/Library/Application Support/MarkD` на macOS и `%APPDATA%/MarkD` на Windows; имя зависит от установленной сборки. Точное расположение журналов открывается через «Помощь → Показать папку с журналами». E2E используют отдельные временные профили.

При обычном сохранении предыдущая версия файла остаётся рядом как `.markd.bak`. Чтобы открыть её вручную, **скопируйте** её под новым именем с расширением `.markd`. Ошибка замены файла больше не приводит к удалению оригинала.

## Разработка и проверки

Используйте Node.js **24.20.0** из `.nvmrc` (минимум 24.19), затем:

```bash
npm ci
npm run dev
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run deps:deprecated
```

E2E запускают Electron с production renderer, скрытым окном и временными данными. CI проверяет macOS arm64, macOS Intel и Windows x64. Наличие workflow не означает успешный прогон: результаты конкретного запуска нужно проверять в Actions.

## Локальная упаковка

```bash
npm run package:mac
npm run package:win
npm run smoke:win # только на Windows, после упаковки
```

macOS: локальная ad-hoc `.app` в `dist-package/mac-arm64/` или `dist-package/mac/` для Intel, с автоматическим smoke. Windows: NSIS `.exe` и `win-unpacked/`. Эти пакеты не включают рабочий канал автообновлений.

## Обновления без ручного скачивания

Встроен `electron-updater 6.8.9`: проверка, загрузка, состояние и контролируемый перезапуск. Для активации нужна **одна переходная установка подписанного выпуска** с HTTPS-каналом. После неё пакеты загружаются внутри MarkD; автоматическая установка при обычном выходе отключена. Без настроенного выпуска интерфейс сообщает, что обновления недоступны.

Настройка сертификатов, подписанного выпуска, сервера и проверка N → N+1 описаны в [руководстве выпуска](docs/releasing.md). Сертификаты и настоящий feed в репозитории не заданы. Подписанные релизы и Windows-обновление не следует считать проверенными по локальным тестам macOS.
