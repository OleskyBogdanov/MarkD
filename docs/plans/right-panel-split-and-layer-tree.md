# Системный UI/UX-рефакторинг MarkD

## Цель

Превратить renderer MarkD из набора крупных экранов с общим CSS-файлом в понятную систему компонентов полноценного desktop-приложения. Главный пользовательский результат первого этапа — удобная правая рабочая панель, где свойства выбранного компонента и структура документа доступны одновременно, но не вытесняют друг друга.

## Принципы

- сохраняем текущий React/Vite/Electron-стек и формат `.markd`;
- разделяем orchestration, layout, feature-компоненты и примитивы управления;
- стили живут рядом с функциональной областью, а общими остаются только tokens/reset;
- используем нативные элементы, видимый `focus-visible`, полноценную клавиатуру и `prefers-reduced-motion`;
- каждое изменение пользовательского поведения закрепляем E2E-сценарием;
- рефакторинг не должен менять сохранение, экспорт, undo/redo и модель документа.

## Этап 1. Правая панель редактора

### Компоновка

- вынести правую панель из `App` в самостоятельный `EditorSidebar`;
- разделить её на верхнюю секцию «Свойства» и нижнюю «Структура»;
- дать секциям независимую прокрутку;
- добавить регулируемый горизонтальный разделитель с мышью и клавиатурой;
- сохранить изменение общей ширины панели.

### Структура документа

- показывать компоненты слоя по аккордеонному принципу: раскрыт максимум один слой;
- не раскрывать слой при простом выборе: раскрытие управляется отдельной кнопкой аккордеона;
- при выборе компонента раскрывать только его слой, чтобы выбранный объект оставался видимым в структуре;
- постоянно показывать только название слоя и число компонентов;
- действия активного слоя оставлять доступными без принудительного раскрытия списка компонентов;
- действия выбранного компонента показывать компактно в той же строке, рядом с названием, и делать доступными по имени;
- всегда показывать страницу компонента.

### Инспектор

- вынести повторяющиеся заголовки, геометрию и сегментированные контролы в отдельные компоненты;
- использовать единый словарь терминов «компонент», «свойства», «структура»;
- у числовой геометрии отделить короткую подпись от единицы измерения и дать полные accessible names;
- следующим шагом разнести панели типов (`text`, `field`, `shape`, `table`, `image`) по отдельным модулям.

## Этап 2. Архитектура renderer

- оставить `App` координатором workspace и файловых операций;
- вынести каркас редактора, верхнюю панель, preview-bar и status toast в презентационные компоненты;
- большие feature-компоненты делить по пользовательской ответственности, а не по случайному размеру файла;
- подписываться в Zustand на минимально необходимые данные там, где это уменьшает перерисовки;
- не создавать компоненты внутри render-функций.

## Этап 3. Система стилей

- `styles/foundation.css`: tokens, reset, focus, базовые состояния;
- `components/start-screen.css`: домашний экран и recent projects;
- `components/toolbar.css`: toolbar, меню добавления/сохранения;
- `features/editor/editor-workspace.css`: shell, header, canvas layout, preview;
- `features/editor/editor-sidebar.css`, `layers-panel.css` и `inspector/inspector.css`: каркас правой панели, дерево слоёв и контролы инспектора;
- `features/editor/project-canvas.css` и локальные стили `renderers/`: страницы и каждый тип renderer-компонента;
- `styles/utilities.css`: status, responsive/reduced-motion, print;
- удалить дублирующие селекторы и оставить предсказуемый порядок импортов.

## Этап 4. UX-состояния и доступность

- проверить hover/pressed/focus/disabled для каждого интерактивного элемента;
- цели управления — не меньше 24×24 CSS px, ключевые — 40×40 px;
- все icon-only кнопки имеют точное доступное имя;
- разделители поддерживают стрелки, Home/End и отражают значение через ARIA;
- динамические статусы остаются в стабильном `role="status"`;
- интерфейс сохраняет работоспособность при уменьшении окна и увеличении текста;
- печать и preview не получают editor chrome.

## Этап 5. Проверка

- typecheck и lint;
- unit-тесты;
- целевые Electron E2E: две секции, независимый scroll, keyboard-resize, аккордеон слоёв, добавление слоя, действия компонента;
- полный E2E-набор и production build;
- визуальный осмотр рабочего экрана в desktop-приложении;
- независимая проверка отдельным субагентом.

## Критерии приёмки

- свойства и структура остаются одновременно доступны и изменяют высоту независимо;
- подробности скрыты у свёрнутых слоёв, раскрыт максимум один;
- выбор компонента синхронно обновляет верхнюю секцию;
- все прежние операции со слоями и компонентами работают;
- `App` не содержит разметку правой панели;
- повторяемые элементы инспектора вынесены в компоненты;
- стили больше не сосредоточены в одном `styles.css` и разложены по владельцам;
- свежие проверки проходят без ошибок, а непроверенные пункты явно отмечены.
