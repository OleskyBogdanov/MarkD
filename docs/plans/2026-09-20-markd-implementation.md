# Реализация улучшений MarkD — 20 сентября 2026

## Объём

Реализованы локальные исправления и подготовка выпуска из [плана](2026-09-20-markd-improvement-plan.md). Подписанное распространение и фактическое обновление установленного Windows/macOS клиента остаются внешним этапом; его нельзя объявлять завершённым по этим тестам.

| Проблема аудита | Реализация | Проверка |
| --- | --- | --- |
| F01: закрытие теряет изменения | Нативный close/before-quit → renderer flush → Save/Discard/Cancel; отмена/ошибка сохраняет окно | E2E cancel, отмена Save As, ошибка записи, сохранение при quit |
| F02: последние символы не сохраняются | Реестр buffered controls, синхронный flush перед чтением актуального store | E2E немедленного Ctrl+S без blur |
| F03: поздний Save очищает dirty новых правок | sessionId, revision, markSaved; повторная проверка после I/O | Unit + E2E задержанного ответа Save |
| F04: native Undo не отменяет объекты | Общий маршрут команд; текстовые undo/redo/delete передаются webContents, объектные — store | E2E Cmd/Ctrl+Z, native commands, clipboard и object Undo/Redo |
| F05: добавление всегда на первый лист | activePageId, выбор страницы мышью/клавиатурой, навигатор, duplicate/move/delete | Unit + E2E добавления на второй лист, удаления/Undo |
| F06: новый документ остаётся в preview | Единый переход сбрасывает режим/selection | E2E new из preview |
| F07: неверный путь Intel .app | `mac/` для x64, `mac-arm64/` для arm64; скрипт запускает локальный CLI напрямую | Проверка кода + CI Intel; локальный smoke arm64 |
| F08: неоднозначные ID/повреждённые изображения | Уникальные page/element/row/column/option IDs; native decode встроенных ресурсов | Unit дубликатов + Electron E2E обрезанного PNG |

Дополнительно: recovery с предыдущей генерацией; чтение `.markd` с ограничением до загрузки; отказ от удаления оригинала при ошибке rename; Save As/копия/шаблон/reveal; пустой документ и создание из шаблона; текущая страница в свойствах; переход из дерева к листу; fit width/page и скрытие sidebar; статус в preview; типизированный единый preload API.

## Обновления и сборки

Встроены electron-updater 6.8.9, state controller, типизированные IPC и панель версии/обновления. Проверяются только release-пакеты с build-time GitHub provider для публичного `OleskyBogdanov/MarkD`. Загрузка по действию пользователя; auto-install-on-quit выключен. Установка проходит сохранение документа; Cancel блокирует её, ошибка установки возвращает документ в рабочий режим. Unit покрывают отключённый feed, coalescing, сетевую ошибку, Cancel и ошибку установки. Они не проверяют реальную криптографическую проверку/установку пакета.

Созданы verify и release-candidate workflows для macOS arm64/Intel и Windows x64. E2E используют production renderer и переносимые временные пути/репозиторный PNG вместо macOS-only изображения. Local ad-hoc упаковка отделена от signed release. Схема обеих release-конфигураций проверена установленным electron-builder 26.15.3.

Инструкции по сертификатам, GitHub Releases и последовательности публикации — [docs/releasing.md](../releasing.md). Ветка `codex/markd-reliability-updates` опубликована с разрешения владельца. Подписанный release не запускался.

Первые прогоны обнаружили два недостатка самих E2E: сравнение viewport-координат до/после автопрокрутки и ограничение кадров скрытого окна Windows. Drag/Undo теперь проверяются относительно листа в окне 1024×768. На Windows CI используются обычные видимые окна; повторный `setBackgroundThrottling(false)` удалён, поскольку эта настройка уже была в приложении и не устраняла ограничение скрытого compositor. Windows E2E прошли за 1,2 минуты вместо 9,5 минут с тайм-аутами. Проверки перемещения и Undo сохранены.

Скриншоты редактора, узкого окна, preview и экспортированный PDF сохраняются в артефактах `checks-<runner>`. Визуально просмотрены редакторы macOS arm64/Intel и Windows, а также отрисованные PDF macOS arm64/Windows. Кириллица читается, панели редактора не попадают в PDF; оба проверенных PDF содержат одну страницу. Stress-сценарий намеренно задаёт длинные значения и слишком низкий текстовый блок: обрезание содержимого фиксированными рамками не означает его автоматическое размещение. Эти снимки не являются утверждёнными визуальными baseline.

Среда: macOS arm64, Electron 44.1.1; финальные команды — Node 24.20.0 из `.nvmrc`.

- `npm run typecheck` — успешно.
- `npm run lint` — успешно, без warnings.
- `npm test` — 45 тестов в 8 файлах.

- `npm run deps:deprecated` — точный allowlist; добавлена транзитивная lodash.isequal из updater 6.8.9. npm install сообщил 0 vulnerabilities на момент установки.
- Сборка `.app`, `codesign --verify --deep --strict`, 5 fuses и запуск packaged renderer — успешно, runtimeErrors пуст.

- Визуально просмотрены редактор при 1024 px и экспорт PDF. PDF — одна A4-страница, без служебных панелей/кнопок. Артефакты: `output/verification/editor-1024.png`, `preview.png`, `proposal.pdf`, `pdf-page.png` (локальные, не коммитятся).

## Границы проверки и следующие ворота выпуска

Windows runtime/NSIS и Intel runtime проверены в GitHub Actions; локальная машина — macOS arm64. Windows runner использует Windows Server 2022, поэтому приёмка на пользовательских Windows 10/11 остаётся частью выпуска. Доверенные сертификаты, нотариализация и N → N+1 на реально установленных подписанных версиях не предоставлены и не подтверждены. Для production-канала нужно пройти матрицу обновлений из release guide. Для версии без обновлятора потребуется одна переходная ручная установка.

Автоматические OS-specific визуальные baseline пока не утверждены; визуальный просмотр артефактов обеих ОС выполнен. Оптимизация крупных документов и переход с JSON/base64 на ZIP остаются отдельными задачами по результатам измерений; сейчас формат и schemaVersion не менялись. История undo больше не делает лишнюю глубокую копию при перекладывании immutable snapshots, но остальные изменения структуры не выдаются за полную оптимизацию больших файлов.

## Уточнение источника обновлений: GitHub Releases

По выбору владельца generic HTTPS feed заменён на GitHub Releases. Каналы `latest-arm64`, `latest-x64`, `latest` используют отдельные metadata в одном стабильном релизе. Workflow создаёт полный draft только после успешной сборки и smoke всех трёх платформ. Для клиента не нужны PAT или отдельный сервер. Текущая подготовленная версия — 0.4.1; существующий v0.4.0 не менялся. Детали и обязательные проверки подписанного обновления — в [руководстве](../releasing.md).

Локальные проверки GitHub-интеграции: typecheck/lint/deprecated dependencies, 49 Vitest-тестов, 7 проверок release-скриптов, 43 Electron E2E. Тестовая ad-hoc ZIP-сборка builder 26.15.3 создала настоящий `latest-arm64-mac.yml`, blockmap и `app-update.yml`; SHA-512 ZIP совпал с metadata. Эта сборка не публиковалась и не является подписанным production-кандидатом. Read-only preflight подтвердил публичность репозитория и свободный тег v0.4.1.

Финальный [Verify desktop #35524704882](https://github.com/OleskyBogdanov/MarkD/actions/runs/35524704882) для `a817dc0c22396dd7afc1360132ca1089dfac6ee7` завершился успешно на macOS arm64, macOS Intel и Windows x64. На каждой платформе прошли typecheck, lint, проверка deprecated dependencies, 49 Vitest-тестов, 7 проверок release-скриптов и 43 Electron E2E, затем упаковка и smoke. На Windows проверен установленный NSIS-клиент; на обеих macOS — запуск `.app` и пять fuses без runtime errors. Это проверка обычных пакетов; подписанный release workflow и реальная установка обновления N → N+1 ещё не запускались.

Первый прогон выявил гонку в E2E отмены закрытия: тест повторно закрывал окно до завершения предыдущего IPC-ответа. Тест теперь ожидает `document:closeResponse` перед следующим действием; проверки отмены и ошибки записи сохранены. Два затронутых сценария дополнительно прошли по десять локальных повторов.
