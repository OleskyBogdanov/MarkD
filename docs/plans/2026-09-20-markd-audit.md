## Что уже сделано хорошо

- Есть разделение `main` / `preload` / `renderer` / `shared`. Renderer не имеет прямого Node.js-доступа; включены sandbox, context isolation, CSP и запрет новых окон.
- Проект `.markd` самодостаточен: данные изображений встроены; доступны локальные шрифты и миграция старых схем. Проверен перенос копии на чистый профиль.
- Работают слои, история действий, таблицы с продолжением, изображения, предпросмотр и PDF. Это подтверждено существующими E2E, а не только чтением кода.
- Сохранение использует временный файл, `fsync` и `.bak`; при нормальной записи есть защита предыдущей версии.
- Есть журналирование ошибок main/renderer, error boundary и проверка упакованной macOS-сборки.

Переписывать приложение или менять стек для решения найденных проблем не требуется.

## Подтверждённые ошибки

P1 — исправить до следующего распространяемого выпуска; P2 — ближайшая итерация; P3 — поддержка и полировка.

### F01 · P1 · Закрытие окна теряет несохранённый документ

**Воспроизведение:** создать проект → добавить текст → закрыть окно системной кнопкой или командой закрытия.

**Получено:** в диагностике `isDocumentEdited() === true`, окно закрылось, число renderer- и native-диалогов равно нулю. Пользователю не предлагают сохранить правки.

**Причина:** `src/main/ipc/ipcHandlers.ts:387` только вызывает `setDocumentEdited`. Это индикатор изменения, а не защита закрытия. В `src/main/main.ts:194` и `src/main/windows/createWindow.ts` нет close guard; подтверждение `src/renderer/App.tsx:93` вызывается только отдельными действиями внутри UI.

**Исправление:** единый протокол «Сохранить / Не сохранять / Отмена» для закрытия окна, выхода, открытия другого проекта и установки обновления. Ошибка или отмена сохранения должны отменять закрытие. Проверять не только committed store, но и ещё не отправленный текст из полей. Автовосстановление после аварии — отдельная защита, обычный close guard его не заменяет.

### F02 · P1 · Быстрое сохранение записывает предыдущий текст

**Воспроизведение:** сохранить блок с текстом `BEFORE` → заменить его на `AFTER-QUICK-SAVE` → немедленно нажать Ctrl+S, не покидая поле. На macOS обработчик также принимает Cmd+S; диагностический запуск использовал Ctrl+S.

**Получено:** в поле `AFTER-QUICK-SAVE`, в реально записанном `.markd` — `BEFORE`.

**Причина:** `src/renderer/components/ui/BufferedTextControl.tsx:22` держит черновик локально и отправляет его в store через 180 мс или на blur. `src/renderer/App.tsx:156` сериализует проект без принудительной фиксации активного ввода. При размонтировании буфера таймер очищается без commit. Экспорт и смена проекта тоже требуют проверки этого контракта; потеря текста именно в PDF в этом аудите отдельно не воспроизводилась.

**Исправление:** явный `flushPendingEdits()` перед Save, Save As, PDF и навигацией, затем чтение актуального состояния store. Нельзя исправлять это произвольной задержкой 180–200 мс. Включить IME/composition в регрессионные сценарии.

### F03 · P1 · Завершение старого сохранения снимает флаг новых правок

**Воспроизведение:** начать сохранение → пока ответ IPC не пришёл, изменить текст → дождаться ответа.

**Получено:** при контролируемой задержке IPC snapshot содержит `BEFORE`, интерфейс содержит `EDIT-WHILE-SAVING`, кнопка уже называется `Сохранить` без отметки изменений. На снимке `save-race.png` виден ложный статус «Сохранено».

Диагностика подменяла только длительность ответа `project:save`, сохраняя переданный snapshot. Это детерминированная проверка гонки, а не измерение частоты её появления на обычном диске.

**Причина:** `src/renderer/App.tsx:171` безусловно выполняет `setDirty(false)` после `await`; редактирование холста остаётся доступным. Для смены проекта также нет проверки идентичности документа, которому принадлежит завершившаяся операция.

**Исправление:** хранить `documentId`, ревизию документа и сохранённую ревизию. Ответ Save подтверждает только конкретный snapshot. Новые изменения остаются dirty; результат старой операции не меняет путь другого документа. Один координатор операций должен обслуживать меню, клавиатуру и toolbar.

### F04 · P2 · Cmd+Z не отменяет структурные действия

**Воспроизведение:** добавить текстовый блок → перевести фокус на кнопку toolbar → Cmd+Z → нажать кнопку «Отменить».

**Получено:** число текстовых блоков `2 → 2 → 1`. Горячая клавиша не отменяет добавление, кнопка отменяет.

**Причина:** `src/main/main.ts:119` задаёт нативные роли `undo`/`redo`, работающие с историей текстового контрола. Кнопки вызывают историю Zustand. IPC-команды undo/redo существуют, но native menu их не отправляет.

**Исправление:** определить единые команды с учётом фокуса: в текстовом поле — согласованная история текста, вне поля — история документа. Проверить Cmd/Ctrl+Z, Shift+Z/Ctrl+Y и Backspace/Delete при вводе, чтобы клавиша удаления символа не удаляла выбранный объект. Ошибка Backspace как отдельный runtime-дефект пока не доказана.

### F05 · P2 · Вторая страница не становится целью добавления

**Воспроизведение:** добавить страницу → нажать внутри второго листа → «Добавить → Текст».

**Получено:** текстовые элементы распределены по страницам `[2, 0]`; новый блок оказался на первом листе.

**Причина:** `src/renderer/App.tsx:299` и `:304` явно используют `project.pages[0]`; импорт изображения делает то же в `:316`. Активной страницы в store нет. В инспекторе фон меняется только для первого листа.

**Исправление:** `activePageId`, видимое выделение активного листа, добавление на выбранную страницу и управление страницами. Продолжения таблиц нужно отличать от самостоятельных страниц данных.

### F06 · P2 · Новый документ наследует режим предпросмотра

**Воспроизведение:** открыть предпросмотр → создать документ через команду системного меню.

**Получено:** новый документ остаётся в preview, кнопки добавления нет; приходится вручную возвращаться к редактированию.

**Причина:** `handleCreateProject` (`src/renderer/App.tsx:139`) не устанавливает `renderMode='edit'`. Аналогичный пропуск есть в `applyOpenedProject` (`:96`), но открытие из preview отдельно не воспроизводилось.

**Исправление:** единая инициализация сессии документа: режим, путь, выделение, активная страница и состояния операций.

### F07 · P2 · Упаковка для Intel Mac ищет неверный каталог

**Подтверждение по установленной зависимости:** `getArchSuffix(Arch.x64, undefined)` возвращает пустую строку. `app-builder-lib/out/platformPackager.js:90` формирует `dist-package/mac`, тогда как `scripts/package-mac.mjs:18` и `scripts/smoke-packaged-app.mjs` ожидают `dist-package/mac-x64`.

arm64 использует `mac-arm64` и прошёл упаковку. Ошибка x64 подтверждена вычислением путей, а не запуском на Intel Mac.

**Исправление:** получать фактический путь артефакта из результата сборки либо явно согласовать пути. Добавить независимые проверки обеих macOS-архитектур.

### F08 · P2 · Валидация принимает неоднозначные и повреждённые проекты

`src/shared/projectSchema.ts:201` проверяет уникальность слоёв и assets, но не ID страниц и элементов. Вызовы `projectSchema.safeParse` с продублированной страницей и с дублированным элементом вернули `success: true`. Это создаёт неоднозначность при `.find`, выделении и изменении по ID.

`ensureSafeProjectSnapshot` принял asset с `data:image/png;base64,iVBORw0KGgo=` — только PNG-заголовком без изображения. `detectImageMimeType` проверяет magic bytes, а не декодируемость. Это подтверждённый пробел целостности; эксплуатация как уязвимость не утверждается.

**Исправление:** определить области уникальности ID страниц, элементов, строк/колонок и options; отклонять дубликаты. Проверять декодирование и разумные размеры изображений до принятия в проект. Сохранить тесты для повреждённых данных, не менять валидные старые документы молча.

## Удобство работы: предлагаемые изменения

1. **Состояние документа всегда понятно.** Показывать «Есть изменения», «Сохраняется», «Сохранено в 14:32» и доступный путь файла. Точка в названии кнопки плохо объясняет состояние. Ошибки не должны скрываться вместе с режимом редактора.
2. **Сохранение одним действием.** Основная кнопка сразу сохраняет, стрелка открывает «Сохранить как…» и «Сохранить копию». Сейчас каждое сохранение мышью требует меню; полноценной команды Save As для уже открытого файла в UI нет.
3. **Настоящая работа со страницами.** Навигация, выбранный лист, перемещение и дублирование, добавление элементов на выбранный лист, свойства фона этого листа. `duplicatePage`/`movePage` в store уже есть, но пользовательского управления ими нет.
4. **Шаблон не перезаписывается случайно.** При открытии «как шаблон» создавать новый документ без исходного пути. Сейчас шаблон — обычный `.markd`; открытие через «Открыть» присваивает его путь текущему проекту.
5. **Пустой документ и КП — разные стартовые варианты.** Сейчас новый проект сразу содержит коммерческое предложение и таблицу. Дать выбор «Пустой документ» / «Коммерческое предложение» / «Из шаблона».
6. **Масштаб под рабочую область.** На снимке E2E при ширине 1024 px правая часть A4 при 100% требует горизонтальной прокрутки. Добавить «По ширине» / «Вся страница», сохраняя возможность 100%; скрытие свойств освободит место.
7. **Повседневные команды.** Дублирование объекта, понятное удаление, переход к выделенному элементу из дерева, список горячих клавиш. Приоритет — единая семантика команд, затем новые комбинации.

Это предложения по продукту, а не утверждение, что каждая отсутствующая возможность является ошибкой.

## Архитектура и производительность

Граф кодовой базы использован для поиска символов и связей, затем выводы сверены с исходниками. Граф ошибочно связал одноимённые `loadRecentProjects` в renderer/main и не содержал тестовые файлы; эти места проверены непосредственно. Граф — навигация, не доказательство реального IPC-вызова.

Основные зоны усложнения — `App` с жизненным циклом документа и `useEditorStore` с историей и всеми операциями. `App` подписан на весь project; `LayersPanel` пересобирает дерево по страницам, `ProjectCanvas` пересчитывает пагинацию при изменении проекта. `applyHistory` копирует каждый элемент даже для изменения одного текста, а undo/redo глубоко копируют и assets.

Синтетическое измерение 25 операций `updateText` без React-рендера на этой машине:

| Элементов | Медиана | p95 |
| --- | --- | --- |
| 100 | 0,14 мс | 0,38 мс |
| 1 000 | 1,44 мс | 1,98 мс |
| 5 000 | 6,59 мс | 8,72 мс |

Это подтверждает рост стоимости обновления store, но не доказывает заметные пользователю лаги. До оптимизации измерить полный input-to-paint, память и PDF на типичных больших документах. Затем применять structural sharing, подписки на отдельные элементы и виртуализацию страниц по результатам профилирования. Массовая мемоизация без измерений не нужна.

Рекомендуемые небольшие границы модулей: `documentSession` (путь, ревизии, открытие/закрытие), `documentCommands` (единые UI/native команды), `pendingEdits` (буферы), `recoveryService`, `updateService`. Геометрию и пагинацию таблиц стоит тестировать как чистые функции. Переход на иной формат проекта не является обязательным условием ни этих исправлений, ни автообновления.
