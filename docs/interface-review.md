# Работа с элементами редактора

Основное действие: редактировать выбранный элемент на странице.
Приоритеты: документ на холсте, инструменты выбранного элемента, структура слоёв.
Сохраняются все настройки содержимого, оформления, геометрии, изображений,
фигур, полей, таблиц и документа, а также управление слоями и историей.
Постоянная правая панель свойств заменяется горизонтальными инструментами:
редкие настройки открываются по группам, выравнивание таблицы доступно сразу.
Новые декоративные блоки и дополнительные зависимости не требуются.

Layout: редактор — неподвижные инструменты над рабочей областью ->
scroll-body-shell; scroll owner: `.canvas-col`; структура независимо
прокручивается в `.inspector-layers-pane`, настройки — в открытом
`.inspector-section-content`; вся оболочка не прокручивается.
Группы инструментов переносятся по ширине, всплывающие настройки не обрезаются
границами toolbar. На узком экране структура открывается поверх холста.

## Подтверждённые причины

- Выбор элементов ограничен активным слоем одновременно в store и canvas.
  Доступный элемент другого слоя отображается в режиме preview и не выбирается.
- Выравнивание в инспекторе меняет `table.style.align` для всей таблицы.
  В воспроизведении три столбца поменяли `left` на `right`. Изменение соседних
  столбцов следует из области действия команды, а не из совместной ссылки
  на стиль. Действия для отдельных строк и столбцов уже существуют в store,
  но интерфейс их не предоставляет.
- Правила строк имеют приоритет над правилами столбцов, затем действует
  значение всей таблицы. Этот порядок должен сохраняться при редактировании,
  сохранении, повторном открытии, предпросмотре и экспорте.

## Аудит корректности и платформ

Замечания ниже установлены по исходникам; сценарии с Finder и аварийным
завершением renderer отдельно не воспроизводились.

| P2 | `src/main/main.ts:236`, `:267`, `:301` | После закрытия последнего окна процесс macOS остаётся активным. Обработчик `open-file` ставит файл в очередь, но не создаёт окно; очередь откладывается до последующей активации приложения. Стоит создавать окно при таком запросе ОС и обрабатывать очередь после загрузки. |

Если renderer затем зависнет до `CLOSE_RESPONSE`, запрос останется в map, а повторные попытки закрытия вернут `false`. Нужен путь восстановления после подтверждения получения запроса. |
| P2 | `src/main/storage/markdPaths.ts:30` | Очистка имени файла сохраняет зарезервированные Windows имена `CON`, `NUL`, `COM1`, `LPT1`, в том числе перед расширением. Нужна нормализация зарезервированных базовых имён и проверка сохранения на Windows. |

Независимый аудит не выявил дополнительной подтверждённой ошибки в preload
и реализации атомарной записи проекта в пределах просмотренных путей.
Это не является доказательством корректности всего приложения.

Для лаконичности новые инструменты используют существующие инспекторы,
компонент выравнивания и действия store. Разделитель двух правых панелей
и его состояние больше не нужны. Store редактора остаётся крупным модулем;
разделение по операциям документа, слоёв и таблиц разумно рассмотреть отдельным
изменением с сохранением контрактов истории и сессии.

В `.github/workflows/verify.yml` предусмотрены macOS ARM64, macOS Intel
и Windows: типы, lint, unit, Electron E2E, упаковка, установка и запуск
Windows сборки. Наличие workflow не означает, что текущие изменения
прошли эти задания. На рабочей станции доступна macOS ARM64; нативный запуск
Windows, NSIS installer и macOS Intel здесь не проверены.

## Проверки изменений

Среда проверки: Node.js 24.20.0 из `.nvmrc`, npm 11.19.0,
macOS ARM64. Зависимости установлены через `npm ci`, lockfile не менялся.

- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` прошли.
  Vitest: 54 теста в 11 файлах. Регрессия выбора чужого слоя до исправления
  падала на `selected: none` вместо выбранного элемента.
- Полный Electron E2E запуск: 42 сценария прошли, два остановились
  на устаревших предположениях о расположении команд интерфейса.
  После адаптации оба сценария отдельно прошли: суммарно проверены все
  44 сценария. Пройденные сценарии повторно не запускались.
- Проверены отдельные столбцы и строки, обе оси, приоритет правил,
  Undo/Redo, сохранение и повторное открытие; выбор слоя по клику,
  защита заблокированных и скрытых слоёв; свойства всех типов элементов,
  предпросмотр, PDF, буфер обмена, восстановление и работа с документом.
- Для семи контекстов (документ и шесть типов элементов) сохранены 111
  изображений в окнах 1440, 1024 и 390 px. Захвачены все группы настроек.
  Автоматически проверены границы каждой всплывающей панели, вход через
  Tab и возврат фокуса к кнопке через Escape. Снимки и манифест находятся
  в `output/interface-review/surfaces/`, исходные снимки документа
  и таблицы — в `output/interface-review/`.
  Независимая проверка обнаружила неверную подпись первоначальных снимков
  изображения: добавленное изображение ещё не было выбрано. Этот контекст
  переснят после явного выбора и проверки заголовка панели. Актуальный
  набор определяется `surfaces/manifest.json`; файлы вне него не входят
  в свидетельства проверки.
- Проверена упаковка `dist-package/mac-arm64/MarkD.app`, ad hoc подпись
  через `codesign --verify --deep --strict`, пять Electron fuses и запуск
  renderer без ошибок в журнале.

390 px — дополнительная проверка узкого окна; штатный минимальный размер
desktop окна остаётся прежним. Панель инструментов в узком окне прокручивается
по горизонтали, структура скрывается автоматически. Захваты при светлом
и тёмном системном предпочтении выполнены; отдельной тёмной темы продукт
не предоставляет. Полная сертификация WCAG, проверка VoiceOver/NVDA,
нативный Windows и Intel Mac не выполнялись.

## Независимое заключение

Две независимые проверки завершились с PASS для объёма этой задачи:
функциональный анализ исходников и визуальный осмотр. Визуальный проверяющий
просмотрел все 111 актуальных снимков: 42 состояния интерфейса и 69
всплывающих панелей, а также шесть исходных снимков документа и таблицы.
Новых подтверждённых блокирующих дефектов не выявлено.

Выполнен один раунд проверки продукта; исправление ошибочно подписанных
снимков изображения относится к сбору свидетельств, код продукта при этом
не менялся. Визуальная проверка заняла 7 минут 17 секунд. Сравнение
«до / после» оценивает компоновку: масштаб и положение документа различаются,
поэтому попиксельная идентичность не заявляется.

Сохранены ограничения проверки: исходные снимки есть только для документа
и таблицы; остальные контексты проверены в текущем состоянии. Скриншоты
не доказывают соответствие требованиям контраста или работу скринридера.
Предварительные замечания P2 в main/storage приведены выше как отдельный
результат аудита и не исправлялись в рамках изменения интерфейса.
